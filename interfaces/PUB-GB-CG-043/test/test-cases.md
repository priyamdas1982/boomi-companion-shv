# Test cases: PUB-GB-CG-043

Derived from design/spec.md and design/mapping.md only (revision 5, approved 2026-10-08).

Round 1, mode write-cases. Nothing has been deployed or executed.

## Scope and common setup

- Process under test: `[Publisher]-[PUB-GB-CG-043]-[Lead]-[Customer Portal]-[GB-CG]` (C1), exposed by API Service `PUB-GB-CG-043 Lead API` (C2).
- Environment: `1-DEV` (693e8bc2-46f8-4c7f-8259-8dcf6cf0f264), account `shvenergynv-6R344K`. Before any run, `boomi-deploy.sh --list-environments` must show it as test or development. Never production (CLAUDE.md; spec "Requirements", D1).
- Endpoint (spec "Endpoint and authentication"): `POST /ws/rest/gb-cg-leads/v1/leads`, sent with `boomi-wss-test.sh --path /ws/rest/gb-cg-leads/v1/leads --method POST --data <payload file>`. Basic auth comes from `SERVER_USERNAME` / `SERVER_TOKEN` in `.env` inside the script. No credentials are in any payload or in this file.
- Results: `boomi-execution-query.sh --process-id <C1 id>`, then `--execution-id <id> --logs` for every executed case.
- Payload files are single-line, with no trailing newline. `boomi-wss-test.sh` sends a file with `curl -d @file`, which strips CR and LF characters, so a multi-line file would not reach Boomi byte-for-byte. The bytes in the file are therefore exactly the bytes sent, and the "byte-for-byte" checks compare the Kafka message with the file.
- Response time: read from the `--- HTTP <code> (<seconds>s) ---` line printed by `boomi-wss-test.sh` (client side, includes network).
- Kafka observation: the spec requires checks on the topic content (message count, body byte-for-byte, no headers, no key). The skill has no tool that reads a Confluent topic. The execute run needs one of these, in this order: (1) read access to `gb-cg.q.leads.in.insert` and `gb-cg.q.leads.in.retry` in `1-DEV` given by the user (Confluent UI or a consumer); (2) otherwise, the process log and Process Reporting for the C7/C8 produce steps (document count and the outbound document), and the topic-level checks are recorded as "partly verified (Boomi side only)". The tester never changes the topics, the `[Confluent_NL-HQ_Kafka]` connection or its `1-DEV` extension values to make a check possible.
- Facade observation: the process log of C1 shows the Process Call to `[MED] (sub) CACHE Notification Facade` (C9) and its subprocess steps inline (subprocess runs have no own execution record).
- Prerequisite (spec "Topics"): both topics exist on the cluster that `[Confluent_NL-HQ_Kafka]` points to in `1-DEV`. If not, stop and report to the orchestrator.
